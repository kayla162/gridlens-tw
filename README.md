## 為什麼做這個

想問的人不會寫 SQL，會寫 SQL 的人不知道要問什麼。這個系統讓人直接用中文問，系統產生 SQL、查台電公開資料，用文字、數字和圖表回答。

但只會翻譯還不夠。問「2025 年台灣太陽能發了多少度？」查得到數字，可是那份資料只收台電**自建**場站，約佔全國風光地熱的 **3～4%**——數字看起來完全正常，你不會察覺它不是你要的。所以系統的重心在**守門**：算不出來的題目直接擋下並建議問法；答得出但有範圍限制的，照答並把限制寫在旁邊。即時資料也照同一原則：數字旁一定標出資料時間、收集狀態與異常機組。

## 查詢與守門

```mermaid
flowchart LR
    Q[中文問題] --> S[產生 SQL<br/>規則或 LLM]
    S --> G1{安全守門<br/>語法樹檢查}
    G1 -- 不安全 --> X[拒絕並說明]
    G1 -- 通過 --> G2{語意守門<br/>答得出來嗎}
    G2 -- 答不出 --> X
    G2 -- 通過 --> P[依帳號電廠改寫]
    P --> DB[(唯讀 power.db)] --> A[摘要＋圖表＋SQL＋出處]
```

- **安全守門**用 sqlglot 拆語法樹檢查，只准查審核過的中文語意檢視；SQL 攻擊題庫 16／16 全攔。
- **語意守門**分「拒答／揭露限制／請你講清楚」三級，資料陷阱寫在資料庫裡，不靠提示詞。
- **權限在後端執行**：SQL 通過安全檢查後才由程式依帳號改寫，AI 想繞也繞不過去。同一句「列出台中發電廠所有設備」，全權限帳號 14 筆、林口帳號 0 筆。
- **離線就能用**：預設離線規則模式，不需要 API key；線上模式的 key 只存在記憶體、重啟即失效。

## 即時收集器

台電的 `d006001` 只提供「現在」這一筆，錯過就沒了。收集器（`src/ingest/realtime/`）把它變成可以回頭查、可以重建的資料：

- **不漏抓**：時段開始後 5:20 第一次抓，沒更新就 60 秒後再試；連續失敗自動拉長間隔，遵守 `Retry-After`；帶 ETag 做條件式請求。
- **先封存再入庫**：每份原始回應以內容雜湊去重、gzip 封存；`realtime.db` 隨時能從封存**重建**，重建結果與逐筆入庫的 checksum 相同（有測試釘住）。
- **驗證後才採用**：結構錯誤整份拒收（封存仍保留）；數值問題照收但標記品質；11 列小計逐類核對。
- **不會因單一失敗停下**：決定檔被 Excel 存壞、封存寫不進去、資料庫損壞，都只警告或自動復原；真的損壞（`SQLITE_CORRUPT`）才移到旁邊重建。
- **有帳可查**：每次抓取都留紀錄；每日彙總只算可信值，缺口分成「收集器沒跑／抓取失敗／拒收」三種；原始明細保留 14 天、彙總後才清。
- **人工決定、不猜**：204 個機組的粒度與所屬電廠逐一人工確認，執行時不做字串比對推測。
- **單一實例**：作業系統檔案鎖保證只有一份在跑；`即時收集啟動.bat` 異常時自動重啟，可設定開機自動啟動。

## 即時發電面板

「資料總覽」頁最上方：

![GridLens TW 即時發電面板：綠燈與最新時段、各類型淨發電量與裝置容量、通訊異常機組數，以及今日每 10 分鐘的各類型出力趨勢](readme_realtime.png)

> 趨勢圖從 08:50 才有線：收集器設定成電腦開機、登入後才啟動並開始呼叫台電 API，之前的時段沒有收到資料。面板照實以空白呈現，不補 0；`d006001` 只提供「現在」這一筆，錯過的時段目前補不回來（`d006010` 歷史資料可以回補，但它晚約四個月，補的是收集器啟動以前的日子，見 RT-2）。

- **燈號**：綠＝收集中且資料新、黃＝落後超過 30 分鐘、灰＝收集器停止或無資料，附最新時段與今天收到幾個時段。
- **各類型總出力**：只加總「正常」的值，通訊異常的機組另計；缺值是空白不是 0；儲能（放電）與儲能負載（充電）分列不相抵。
- **今日趨勢**：每 10 分鐘一點，沒抓到的時段斷線；附可展開的數字表。前景時每 60 秒更新，背景暫停。
- **權限與查詢一致**：電廠帳號只看本廠＋共用，數字拆成「本廠」「共用」兩欄；兩邊電廠名冊對不上就拒絕（409）；訪客政策為 `denied` 時只看得到狀態。
- **誠實揭露**：資料落後、收集器停止、品質警告、非今日資料都在數字旁說明；品質警告的細節涉及全系統，只給全電廠帳號。
- **不經過 Text2SQL**：寫死的 SQL、每次請求唯讀開檔讀同一份快照；收集器更新後網頁不必重啟。

## 用中文查即時資料

問句帶「現在、今天、昨天」等用詞時，查詢中心改查 `realtime.db`（RT-3b）：

- **用詞決定查哪個資料庫**，不是機組名：兩邊有約 21 個同名機組。「哪些機組目前維修中」照舊查歲修排程。
- **兩個資料庫不混用**：同一句 SQL 同時查 `v_rt_*` 與歷史檢視直接拒絕，因為兩邊的機組名稱沒有對照。
- **數字旁一定有資料時間**，並揭露落後、收集器停止、估算發電量、資料完整度、儲能相抵與彙總列。
- **離線規則先接**，接不住的交給 LLM；可以接本機的 Ollama（`POWERQUERY_LLM_PROVIDER=ollama`），不需要 API key。
- 已除役或不在即時資料裡的機組（例如 `台中#1`）會直接說沒有，並建議相近名稱。
- **歷史回補（RT-2）**：匯入台電 `d006010`（各機組過去發電量，每月更新、晚約四個月）後，「2026年4月台中#5發電量」也答得出來；答案標出數字來自歷史資料，類型合計不含民營電廠。

## 資料治理

資料管理不是 SQL 編輯器。它只管五個有 schema 約束的 CSV 資料槽：

- **先建候選、再審核**：上傳或移除先檢查格式與跨檔品質，用固定的建置程式產生候選資料庫，狀態停在 `pending_review`，查詢完全不受影響。
- **四眼原則**：必須由**另一個**有審核權的帳號核准；提案人不能核准自己的提案（單人例外要明設環境變數，且照樣留痕）。
- **原子切換、可回退**：核准後驗證 checksum 才切換，服務不必重啟；每個資料庫版本都能回退。
- **稽核成鏈**：上傳、核准、拒絕、失敗、回退都寫進雜湊鏈稽核紀錄，竄改會被發現。
- **管理是全電廠功能**：電廠帳號不能用管理端點，避免從原始檔繞過權限。
- **即時資料的審核方式**：每筆快照由自動驗證放行；會改變結果的規則（解析程式、機組決定檔、設定）才走 PR 審查。

## 語料學習

這裡的「學習」是新增檢索範例，不是微調模型：

- **六道自動檢查**：去識別、重複、題庫洩漏、SQL 與語意守門、結果重播、檢索回歸。
- **一律人工核准**：通過檢查也只停在 `pending_review`；核准時以當下的資料與語料基線重新驗證，成功才發布並熱重載索引。
- **不留結果、遮個資**：只存去識別問句、SQL、驗證結果與資料出處，不存查詢結果；Email、身分證、電話等自動遮罩。
- **資料換版就重驗**：資料庫版本變更時備份舊語料、重建索引，已發布的範例退回待審，避免沿用舊資料的答案。
- **題庫不准當訓練資料**：評測題目進不了語料，評測數字才可信。

## 技術

Python＋uv（鎖版本可重現）、SQLite（唯讀開檔；即時資料用 WAL）、sqlglot（語法樹守門）、FastAPI、原生 HTML／CSS／JS（不需 Node）、Plotly.js（鎖版本＋SRI）、自寫字元 n-gram 檢索（離線、不需向量服務）、OpenAI Responses API（僅線上模式）、pytest＋ruff＋GitHub Actions（每個 PR 附合併門檻報告）。

踩過的坑（官方憑證鏈、PowerShell 的 BOM、浮點小計誤判、靜態檔快取、Big5 主控台讀壞開機檔⋯⋯）都記在 [log.md](log.md) 與 [docs/SPEC.md](docs/SPEC.md)。

## 快速開始

**Windows**：點兩下 `啟動.bat`，瀏覽器會開在 <http://127.0.0.1:8765/>（離線模式，不需 API key）。要看即時發電，再點兩下 `即時收集啟動.bat`（每 10 分鐘連線台電一次）；`停止即時收集.bat` 停止，`開機自動啟動-即時收集.bat` 放進 `shell:startup` 就能登入後自動收集。

**開發者**：需要 Python 3.12 以上（`.python-version` 釘在 3.12，uv 會自動選用或下載；3.11 關不掉 SQLite 的雙引號字串相容行為，查詢會拒絕執行）。

```bash
make setup && make db && make serve          # 安裝、建快照、啟動 http://127.0.0.1:8000
uv run powerquery "2026年7月備轉容量率最低是哪一天？"
uv run python -m ingest.realtime status      # 另有 run / once / rebuild / stop
make test-all && make eval                   # 全套測試與離線評測
```

帳號、線上模式、資料管理流程見 [docs/SERVING.md](docs/SERVING.md)；公開服務見 [PUBLIC_OFFLINE_SERVING.md](PUBLIC_OFFLINE_SERVING.md)。
